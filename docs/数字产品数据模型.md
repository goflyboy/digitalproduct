## 一、设计背景与核心目标

### 1.1 设计背景

数字产品系统需要解决的核心问题：

1. **上游数据的多样性**：来自 PLM、ERP、SCM、MES、CRM 等多个系统的产品数据
2. **业务维度的扩展性**：需要支持 SPEC、PARAM、MARKETING、DELIVERY、FINANCE、OPERATION 等多维业务对象
3. **多层级的产品结构**：支持 ProductClass → PartClass → Part 的三层树状结构
4. **继承与定制的能力**：支持从模板到实例的继承，以及实例层级的规格覆盖

### 1.2 核心设计原则

| 原则 | 说明 |
| --- | --- |
| **业务对象快速新增** | 支持快速新增上游的业务对象，不需要修改数据库表结构 |
| **多层数据定制** | 数据层次支持多层结构，并支持自定义与定制化 |
| **语义模型快速构建** | 将上游的 IT 数据快速映射为语义模型 |
| **维护态与发布态分离** | 维护态允许草稿，发布态只接收完整数据包 |

### 1.3 与复杂产品配置模型的关系

```
复杂产品配置模型                           数字产品模型
─────────────────                       ─────────────────
ProductClass                          Module (type=PRODUCT)
PartClass                              Module (type=PART_CLASS)
Part                                   Part
Specification                          BusinessObject (type=SPEC)
Parameter                              BusinessObject (type=PARAM)
SpecValue                              BusinessObjectInstance
（无对应）                              BusinessObject (type=MARKETING/DELIVERY/...)
offersPart                             enabled_parts / disabled_parts
SpecOverride                           business_object_overrides
```

### 2.2 详细实体定义

#### 2.2.1 ProductClass（产品类）

产品类是产品平台的可复用骨架，对应电商的 SPU，本身带版本号可发布多次。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| code | String | 业务编码（如 SERVER_X86、ROUTER_PLATFORM） |
| name | String | 名称（如 X86服务器平台、路由器平台） |
| version | String | 版本号（如 1.0.0） |
| status | Enum | DRAFT / PUBLISHED / DEPRECATED |
| description | String | 描述 |
| effective_from | DateTime | 生效时间 |
| effective_to | DateTime | 失效时间 |

> **关键设计**：ProductClass 自身也携带 SpecValue（如 FormFactor=2U、PowerSupply=DUAL），这些是产品层面的固有属性。

#### 2.2.2 PartClass（部件分类）

部件分类是可配置子模块的分类边界。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| code | String | 业务编码（如 cpu、drive、memory） |
| name | String | 名称（如 CPU、硬盘、内存） |
| product_class_id | UUID | 所属产品类引用 |
| part_kind | Enum | COMPONENT / STORAGE / SERVICE |
| selection_policy | Enum | REQUIRED / OPTIONAL |
| min_cardinality | Integer | 最小数量（默认 1） |
| max_cardinality | Integer | 最大数量（默认 1，0 表示无限制） |
| multi_instance | Boolean | 是否支持多实例（如内存可选多条） |

#### 2.2.3 Part（部件）

部件是 PartClass 的具体实例，如一个明确编码的 CPU 或硬盘。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| code | String | 业务编码（如 cpu1、sd1、md1） |
| name | String | 名称 |
| part_class_id | UUID | 所属部件分类引用 |
| status | Enum | ACTIVE / INACTIVE |
| price | Decimal | 参考价格 |

> **Part 与规格值的关系**：Part 携带固有规格值（SpecValue），如 cpu1.CoreNum=2、sd1.Capacity=3TB。

#### 2.2.4 BusinessObject（业务对象）

业务对象是多维业务数据的统一抽象，涵盖 SPEC、PARAM、MARKETING、DELIVERY、FINANCE、OPERATION 等维度。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| code | String | 业务编码 |
| name | String | 名称 |
| object_type | Enum | SPEC / PARAM / MARKETING / DELIVERY / FINANCE / OPERATION |
| description | String | 描述 |
| schema | JSON | 数据结构定义（字段列表、类型、约束） |
| status | Enum | ACTIVE / INACTIVE |
| defined_on_type | Enum | PRODUCT_CLASS / PART_CLASS / PART |
| defined_on_id | UUID | 定义所在实体的 ID |

#### 2.2.5 BusinessObjectInstance（业务对象实例）

业务对象的具体取值，关联到 Module 或 Part。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| business_object_id | UUID | 关联的业务对象定义 |
| owner_type | Enum | ProductClass / PartClass / Part / ProductInstance |
| owner_id | UUID | 所属实体 ID |
| values | JSON | 实际取值（键值对） |
| effective_from | DateTime | 生效时间 |
| effective_to | DateTime | 失效时间 |

#### 2.2.6 ProductInstance（销售产品实例）

销售产品实例是确定销售边界的可售产品，对标电商的 SKU，本身带版本号。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| code | String | 业务编码（如 S1110、S22、ROUTER_01） |
| name | String | 实例名称 |
| version | String | 版本号 |
| product_class_id | UUID | 引用的 ProductClass（平台骨架） |
| status | Enum | DRAFT / PUBLISHED / DEPRECATED |
| enabled_parts | JSON | 启用的 Part 列表（含 minQty/maxQty/defaultSelected） |
| disabled_parts | JSON | 禁用的 Part 列表 |
| spec_overrides | JSON | 规格覆盖（继承修改） |
| extensions | JSON | 多维扩展数据（Marketing/Delivery/Finance/Operation） |

### 2.3 关系边定义

#### 2.3.1 包含关系（CONTAINS）

ProductClass 包含 PartClass，PartClass 可递归包含子 PartClass。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| parent_type | Enum | ProductClass / PartClass |
| parent_id | UUID | 父实体 ID |
| child_type | Enum | PartClass |
| child_id | UUID | 子实体 ID |
| min_cardinality | Integer | 最小数量 |
| max_cardinality | Integer | 最大数量 |
| selection_policy | Enum | REQUIRED / OPTIONAL |

#### 2.3.2 候选关系（CANDIDATE）

PartClass 到 Part 的候选关系。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| part_class_id | UUID | 部件分类 ID |
| part_id | UUID | 部件 ID |
| enabled | Boolean | 是否启用（实例化时可裁剪） |
| default_selected | Boolean | 是否默认选中 |
| min_qty | Integer | 最小数量 |
| max_qty | Integer | 最大数量 |

#### 2.3.3 规格关系（HAS）

实体与规格值的关联关系。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| owner_type | Enum | ProductClass / PartClass / Part |
| owner_id | UUID | 所属实体 ID |
| spec_code | String | 规格编码 |
| value | String | 规格值 |
| unit | String | 单位 |

#### 2.3.4 覆盖关系（OVERRIDES）

ProductInstance 对基线规格的覆盖。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | UUID | 全局唯一标识 |
| product_instance_id | UUID | 销售产品实例 ID |
| spec_code | String | 被覆盖的规格编码 |
| override_value | String | 覆盖后的值 |
| reason | String | 覆盖原因 |

### 3.2 UC-A1：创建产品类

**用例描述**：创建一个新的产品类（如"路由器平台"），定义其基本属性。

**参与者**：ACT-01 产品数据架构师

**数据来源**：上游系统（PLM/ERP），不需要本地维护

**关键路径**：

1. 产品数据架构师进入"产品建模"模块
2. 选择"创建产品类"，填写产品类基本信息
3. 系统校验产品类 Code 不重复
4. 系统保存产品类数据至维护态
5. 系统返回创建成功通知

**数据模型体现**：

```json
// 创建 ProductClass: ROUTER_PLATFORM（路由器平台）
{
  "code": "ROUTER_PLATFORM",
  "name": "路由器产品平台",
  "version": "1.0.0",
  "status": "DRAFT",
  "description": "面向研发和后端复用的通用路由器平台",
  "productLevel": "ENTERPRISE"
}
```

### 3.3 UC-A2：创建部件分类及规格

**用例描述**：为某个产品类创建部件分类（如"CPU 分类"），并定义该分类的规格属性。

**参与者**：ACT-01 产品数据架构师、ACT-02 产品数据工程师

**数据维护**：假设都需要维护，其中规格走 BusinessObject + 自定义维护的方式

**关键路径**：

1. 产品数据工程师选择目标产品类（ROUTER_PLATFORM）
2. 选择"创建部件分类"，填写分类基本信息
3. 为该分类添加规格定义（BusinessObject）
4. 系统保存部件分类及规格至维护态

**数据模型体现**：

```json
// 创建 PartClass: router_cpu（路由器CPU分类）
{
  "code": "router_cpu",
  "name": "路由器CPU",
  "product_class_id": "ROUTER_PLATFORM",
  "part_kind": "COMPONENT",
  "selection_policy": "REQUIRED",
  "min_cardinality": 1,
  "max_cardinality": 2,
  "multi_instance": false
}

// 创建 BusinessObject: SPEC_CORE_NUM（核心数规格）
{
  "code": "SPEC_CORE_NUM",
  "name": "核心数",
  "object_type": "SPEC",
  "defined_on_type": "PART_CLASS",
  "defined_on_id": "router_cpu",
  "schema": {
    "data_type": "INTEGER",
    "unit": "core",
    "required": true
  }
}

// 创建 BusinessObject: SPEC_MAX_BANDWIDTH（最大带宽规格）
{
  "code": "SPEC_MAX_BANDWIDTH",
  "name": "最大带宽",
  "object_type": "SPEC",
  "defined_on_type": "PART_CLASS",
  "defined_on_id": "router_cpu",
  "schema": {
    "data_type": "ENUM",
    "unit": "Gbps",
    "values": ["10", "40", "100", "400"],
    "required": true
  }
}
```

### 3.4 UC-B1c：建立部件分类与产品的关系

### 3.5 UC-A3：创建 Part 对象

**用例描述**：创建一个具体的 Part 对象，并填写该 Part 对应的规格值。

**参与者**：ACT-02 产品数据工程师

**数据维护**：需要维护，部分属性来自上游系统（如 PLM 提供的规格值），部分属性需要本地维护（如本地编码映射）

**关键路径**：

1. 产品数据工程师选择目标部件分类（router_cpu）
2. 选择"创建 Part"，填写 Part 基本信息
3. 系统根据部件分类的规格定义，自动生成规格值录入表单
4. 产品数据工程师填写各规格的具体值
5. 系统执行业务规则校验
6. 校验通过后，系统保存 Part 至维护态

**数据模型体现**：

```json
// 创建 Part: RTR_CPU_01（路由器CPU部件）
{
  "code": "RTR_CPU_01",
  "name": "路由器双核CPU",
  "part_class_id": "router_cpu",
  "status": "ACTIVE",
  "price": 1500.00,
  "dataSource": "PLM",
  "upstreamRefId": "PLM-CPU-001"
}

// 创建规格值 BusinessObjectInstance
{
  "id": "spec-val-001",
  "business_object_id": "SPEC_CORE_NUM",
  "owner_type": "Part",
  "owner_id": "RTR_CPU_01",
  "values": {
    "value": 2
  }
}

{
  "id": "spec-val-002",
  "business_object_id": "SPEC_MAX_BANDWIDTH",
  "owner_type": "Part",
  "owner_id": "RTR_CPU_01",
  "values": {
    "value": "40"
  }
}
```

### 3.6 UC-A4：销售产品实例化与继承修改

**用例描述**：基于某个产品类创建一个销售产品实例（如"ROUTER_01"），继承产品类的所有 Part，并允许在实例层级修改规格值。

**参与者**：ACT-02 产品数据工程师

**关注点**：体现基础、体现关系的裁剪

**关键路径**：

1. 产品数据工程师选择目标产品类（ROUTER_PLATFORM）
2. 选择"创建销售产品实例"，填写实例基本信息
3. 系统自动列出该产品类下的所有 Part 列表
4. 产品数据工程师选择需要继承的 Part（可全选或部分选择）
