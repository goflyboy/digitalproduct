# ADR-002：CB+New 并行运行策略

## 背景

CB+New是公司现有的产品配置领域数据管理系统，只服务于产品配置场景。

数字产品系统的定位是支持更多业务维度（营销、交付、财务、运维等），两者存在功能重叠区域。

**问题**：在数字产品系统 v1.0 期间，CB+New 和数字产品系统应该如何共存？

**候选策略**：

1. **策略 A（完全替代）**：v1.0 立即接管 CB+New 的所有功能
2. **策略 B（并行运行）**：v1.0 期间两者并行运行，数字产品逐步承接
3. **策略 C（分域运行）**：按业务域划分，CB+New 继续服务配置域，数字产品服务其他域

---

## 决策

**选择策略 B：并行运行**

v1.0 MVP 期间，CB+New 与数字产品系统并行运行，但数字产品系统的通用能力构建**必须能够支持 CB+New 的场景**。

---

## 理由

1. **风险可控**：渐进式迁移降低系统切换风险
2. **能力验证**：并行运行便于验证数字产品系统的能力边界
3. **CB+New 场景覆盖**：第一版必须能支持 CB+New 的所有场景，确保平滑过渡
4. **数据一致性**：并行期间需要设计双写同步机制，确保两套系统数据一致
5. **未来演进**：CB+New 功能逐步融入数字产品，最终实现统一

---



## 实施策略



### 第一阶段：能力对齐（v1.0）

```
┌────────────────────────────────────────────────────────────────────────┐
│                           v1.0 阶段                                    │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│   ┌─────────────────┐              ┌─────────────────┐               │
│   │     CB+New      │              │   数字产品系统    │               │
│   │                 │              │                 │               │
│   │  产品配置域      │   并行运行    │  通用能力构建    │               │
│   │  现有功能        │◀───────────▶│  必须支持 CB+    │               │
│   │                 │   数据同步    │  场景           │               │
│   └─────────────────┘              └─────────────────┘               │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

- 数字产品系统构建通用能力（Module、BusinessObject、ModuleObjectRelation 等）
- 验证数字产品能力可以覆盖 CB+New 的所有场景
- 设计数据同步机制



### 第二阶段：功能承接（v2.0）

- 逐步将 CB+New 的特有功能迁移到数字产品
- 减少 CB+New 的使用范围



### 第三阶段：系统归一（v3.0）

- CB+New 功能完全融入数字产品
- CB+New 系统下线

---



## 后果



### 正面后果

- ✅ 风险可控，平稳过渡
- ✅ 数字产品通用能力得到充分验证
- ✅ 不影响现有 CB+New 用户



### 负面后果

- ⚠️ 需要维护两套系统，短期内运维成本增加
- ⚠️ 需要设计数据同步机制，增加复杂度
- ⚠️ 并行期间可能出现数据不一致风险



### 应对措施

- 设计基于事件的数据同步机制（变更数据捕获 CDC）
- 建立数据对比校验任务
- 制定回滚预案
