## 一、总体数据模型（核心实体及关系）

### 1.1 建模边界与核心结论

电商产品（手机数码等）可以用 **Category -> SPU -> SKU** 三层模型覆盖，因为其核心问题是「选哪个颜色/容量组合」，SKU 是最终可售单元。

复杂产品（服务器、工业设备、PLC 配置器）不同。它的核心问题是：

- 产品由多级部件组成（CPU、内存、硬盘、电源、支架...）
- 每个部件分类下有多个候选 Part
- Part 之间存在数量、兼容、依赖、计算、优选等多种约束规则
- 同一产品平台可派生出多个可售型号（低端 S1110、高端 S22）
- 客户需要通过配置器选择组合，系统校验约束后输出 BOM/报价/交付规格

因此，复杂产品配置需要 **双层元模型 + 三层实例** 的结构：


| 层次            | 解决的问题                                                                                                                                                                        | 核心对象                                                                        | 典型责任人           |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- | --------------- |
| **L1 业务元模型**  | 产品领域允许定义哪些业务类型及语义                                                                                                                                                            | ProductClassType、PartClassType、ProductInstanceType、SpecDefinition、Parameter | IT 与公司级业务/行管人员  |
| **L2 业务对象实例** | 某产品平台的骨架是什么，可售型号如何裁剪                                                                                                                                                         | ProductClass、PartClass、Part、ProductInstance                                 | 产品数据架构师、产品数据工程师 |
| **L3 配置运行实例** | 客户本次模型的逻辑完备性你还需要再审视一下。感觉有的概念，也就是你的整个上下文要一致（包括用例数据、你的 ER 图都要一致），逻辑要完备，但现在感觉有些细微的不一样，你再认真审视一下。比方说下面两个问题，就感觉数据很怪。我始终感觉我们现在用例数据上面提到的、也就是那个样例数据里面的定义，到底对应你的哪一个问题啊？选择什么，是否有效，输出什么 | Configuration、ConfiguredPart                                                | 销售、客户、配置引擎      |


> **说明**：L0 平台基础元模型（OntoObjectType/OntoAttrType/OntoLinkType）由平台架构师负责定义，本文档聚焦业务层建模，暂不展开。

### 1.2 三层概念架构图

> **版本说明**：v1.3 修正 realizes 链路完整性——L1 每个类型（Type）都在 L2 有对应的 realizes 实例，形成完整的类型→实例链。

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ L1 业务元模型（类型/模板层，由 IT 与业务/行管定义）                                               │
│                                                                                                    │
│  ProductClassType ──composedOf──> PartClassType (递归，可嵌套子部件)                                │
│  ProductClassType ──hasSpec──> SpecDefinition (产品层面的物理规格)                                  │
│  ProductClassType ──hasParameter──> Parameter (产品层面的可配置需求)                                 │
│  PartClassType ──hasSpec──> SpecDefinition (部件层面的物理规格)                                    │
│  PartClassType ──hasParameter──> Parameter (部件层面的可配置需求)                                    │
│  ProductInstanceType ──realizes──> ProductClassType (可售产品类型实现产品类型)                        │
└─────────────────────────────┬──────────────────────────────────────────────────────────────────────┘
                              │ instantiate（实例化）
                              ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ L2 业务对象实例（具体数据层，由产品数据架构师维护）                                                 │
│                                                                                                    │
│  【类型→实例 realizes 链路】                                                                        │
│  ProductClass(服务器平台) ──realizes──> ProductClassType                                         │
│  PartClass(CPU/硬盘) ──────────realizes──> PartClassType                                        │
│  ProductInstance(S1110/S22) ──realizes──> ProductInstanceType                                    │
│  ProductInstance ──────────────→ ProductClass (引用平台骨架)                                       │
│                                                                                                    │
│  【结构包含关系】                                                                                  │
│  ProductClass ──contains──> PartClass (1:N，PartClass 递归嵌套子部件)                            │
│  PartClass ──candidate──> Part(cpu1/cpu2/sd1/md1...)                                           │
│                                                                                                    │
│  【规格链路】                                                                                      │
│  Part ──has──> SpecValue (Part 的固有规格值)                                                     │
│  SpecValue ←definedBy── SpecDefinition (规格值由规格定义派生类型约束)                                │
│  ProductClass ──has──> SpecValue (产品类自身也有规格值，如 FormFactor)                            │
│                                                                                                    │
│  【产品实例特有关系】                                                                              │
│  ProductInstance ──offersPart──> Part (裁剪：enabled/defaultSelected/minQty/maxQty/fixed)         │
│  ProductInstance ──overrides──> SpecOverride (覆盖基线规格，如 S22 强制 FormFactor=4U)              │
└─────────────────────────────┬──────────────────────────────────────────────────────────────────────┘
                              │ configure（客户配置）
                              ▼
┌────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ L3 配置运行实例（运行时层，由配置引擎执行）                                                         │
│                                                                                                    │
│  Configuration ──selects──> ConfiguredPart(code, quantity, selected, reason)                       │
│  Configuration ──input──> ConfiguredValue (用户输入的 Parameter 值)                                │
│  Configuration ──produces──> BOM / Price / DeliverySpecification                                   │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

** realizes 链路说明**（三层模型的核心不变式）：

```
L1（元模型层）                              L2（实例层）
─────────────────                            ─────────────────────────────────────────
ProductClassType      ──实例化──>          ProductClass  realizes ProductClassType
PartClassType         ──实例化──>          PartClass    realizes PartClassType
ProductInstanceType   ──实例化──>          ProductInstance realizes ProductInstanceType
                                                  │
                                                  └──→ ProductClass（引用平台骨架）
```

**图例说明**：


| 边/关系 | 语义 | 示例 |
| ---------------------------- | ------------------------------------------------------------- | ------------------------------------------------ |
| `ProductClassType --composedOf--> PartClassType` | 产品类由部件类组成（递归） | SERVER_X86 包含 cpu/drive |
| `ProductClassType --hasSpec/hasParameter--> SpecDef/Param` | 元模型层定义规格和参数 | SpecDef: CoreNum; Param: Sum_Memory |
| `PartClassType --hasSpec/hasParameter--> SpecDef/Param` | 部件元模型定义规格和参数 | SpecDef: Capacity; Param: Sum_Capacity |
| `ProductInstanceType --realizes--> ProductClassType` | 可售产品类型实现产品类型 | PIT_Server realizes PCT_X86 |
| `ProductClass --realizes--> ProductClassType` | 产品类实例化类型（**v1.3 新增**） | SERVER_X86:1.0.0 realizes SERVER_X86 |
| `PartClass --realizes--> PartClassType` | 部件类实例化类型（**v1.3 新增**） | cpu realizes cpu |
| `ProductInstance --realizes--> ProductInstanceType` | 产品实例实现类型（**v1.3 新增**） | S1110:1.0.0 realizes PIT_S1110 |
| `ProductInstance --> ProductClass` | 产品实例引用平台骨架 | S1110 --> SERVER_X86:1.0.0 |
| `ProductClass --contains--> PartClass` | 产品类包含部件分类（结构树） | SERVER_X86 contains cpu/drive |
| `PartClass --candidate--> Part` | 部件分类候选部件 | cpu candidate cpu1/cpu2 |
| `Part --has--> SpecValue` | 部件持有固有规格值 | cpu1 has CoreNum=2, Memory=123 |
| `SpecValue --definedBy--> SpecDefinition` | 规格值受规格定义类型约束 | SpecValue.type 来自 data_type |
| `ProductClass --has--> SpecValue` | 产品类持有固有规格值 | SERVER_X86 has FormFactor=2U |
| `ProductInstance --offersPart--> Part` | 产品实例裁剪部件候选集 | S1110 禁用 cpu3/cpu4 |
| `ProductInstance --overrides--> SpecOverride` | 产品实例覆盖基线规格 | S22 overrides FormFactor=4U |

### 1.3 规格与参数的区别

这是本文模型的核心概念之一。动态属性（dynAttr）分为两类：**规格（Spec）** 和 **参数（Parameter）**，二者在语义、面向角色、可变性上有本质区别：


| 维度          | 规格（SpecDefinition）                                           | 参数（Parameter）                                |
| ----------- | ------------------------------------------------------------ | -------------------------------------------- |
| **语义**      | 产品或部件本身已有的物理特性或性能指标                                          | 销售人员/客户可配置的需求输入                              |
| **面向角色**    | 研发、产品设计人员定义                                                  | 一线产品经理、销售、客户使用和理解                            |
| **是否可手工输入** | 否，继承 ProductClass 或 Part 的固定值                                | 是，可由用户手工输入或修改                                |
| **载体有无对应值** | ProductClass 有 SpecValue，Part 也有 SpecValue                   | Part 无 Parameter 值，参数值在配置阶段由用户输入             |
| **举例**      | 服务器外形 2U（ProductClass）、CPU 核心数 2/4/8/18（Part）、硬盘容量 3TB（Part） | "5400rpm 硬盘总容量 >= 5TB"、"4核 CPU 总内存 >= 512GB" |
| **在模型中的位置** | 定义在 ProductClass 或 PartClass 上，挂在 ProductClass 或 Part 上都有值   | 定义在 ProductClass 或 PartClass 上，Part 无值       |
| **用途**      | 定义产品或部件的固有能力边界                                               | 在配置阶段传递客户需求，驱动求解                             |


**举例说明**：

- `FormFactor = 2U` 是产品类规格：服务器 SERVER_X86 的外形规格天生就是 2U，不可改
- `Capacity = 3` 是部件规格：Part sd1 的硬盘容量天生就是 3TB，不可改
- `Sum_Capacity >= 5` 是参数：客户说我需要至少 5TB 容量，这是需求输入，可以改

## 二、详细数据案例（以服务器产品为例）

> **阅读提示**：本节同时包含 L1 类型定义（ProductClassType）和 L2 实例数据（ProductClass）。二者都出现 `SERVER_X86`，但语义不同：
>
> - **ProductClassType**（L1）定义"服务器类产品类"这一类型元数据（code、domain、modeling_policy），是类型的模板，不含版本。
> - **ProductClass**（L2）是该类型的具体实例（code=SERVER_X86 + version=1.0.0 + FormFactor=2U），产品数据架构师发布后才有版本。
>
> 类比：`ProductClassType` 是"人类的基因定义"，`ProductClass` 是"张三这个人"——都描述"人"，但一个是抽象模板，一个是具体实例。

## 四、新模型与 cruleengine 现有模型的关系

### 4.1 定位说明

新模型是 **数字产品全生命周期的业务事实模型**；cruleengine 主要是 **配置约束的声明和执行模型**。

二者是「业务事实源 → 可执行投影」关系：

```
数字产品模型（源）              cruleengine 执行模型（投影）
─────────────────              ───────────────────────────
ProductClass（含 version）──compile──> Module
PartClass              ──compile──> PartCategory
Part + SpecValue       ──compile──> Part + dynAttr
Parameter              ──compile──> Para
Configuration          <──result─── ModuleInst
ConfiguredPart         <──result──> PartInst / PartCategoryInst
```

### 4.2 概念映射表


| 新建模概念                        | cruleengine 概念   | 关系和差异                                                                         |
| ---------------------------- | ---------------- | ----------------------------------------------------------------------------- |
| ProductClass（含自带 version）    | Module           | Module 含版本、PartCategory、Part、Para，是执行投影；ProductClass 的 version 直接对应 Module 版本 |
| PartClass                    | PartCategory     | 均表达候选分类；现有类已有 selectionPolicy、supportMultiInst 和递归结构                          |
| Part                         | Part             | 基本一致；业务层还需物料主数据、有效期、供应和销售状态                                                   |
| SpecDefinition               | DynamicAttribute | 均支持类型和选项；业务层还需单位、值域、治理和版本                                                     |
| SpecValue                    | dynAttr value    | ProductClass 或 Part 的规格值对应引擎中的属性值                                             |
| Parameter                    | Para             | 对应输入、计算和汇总参数（用户可变的配置需求）                                                       |
| ProductInstance（含自带 version） | 裁剪后的 Module 实例   | 通过 offersPart 边裁剪部件候选集，ProductInstance 自身 version 不再引入 ProductInstanceVersion |
| ConfigurationSolution        | ModuleInst       | ModuleInst 承载数量、优先级值和分类实例                                                     |
| ConfiguredPart               | PartInst         | 对应 quantity、selected、hidden 和选中属性                                             |
| offersPart 边                 | 裁剪后的候选集          | 通过 enabled/disabled 边表达，与引擎的 PartCategoryInst 关联                              |


### 4.3 MultiPCTest 样例映射

基于 `MultiPCTest.java` 中的 `MultiPCConstraint` 类：


| 新建模                          | cruleengine                          | 示例                                     |
| ---------------------------- | ------------------------------------ | -------------------------------------- |
| PartClass: drive             | PartCategoryVar drive                | 硬盘部件分类                                 |
| PartClass: cpu               | PartCategoryVar cpu                  | CPU部件分类                                |
| SpecDefinition: Speed        | @DAttrAnno(code = "Speed", ...)      | 转速属性                                   |
| SpecDefinition: Capacity     | @DAttrAnno(code = "Capacity", ...)   | 容量属性                                   |
| SpecDefinition: CoreNum      | @DAttrAnno(code = "CoreNum", ...)    | 核心数属性                                  |
| SpecDefinition: Memory       | @DAttrAnno(code = "Memory", ...)     | 内存容量属性                                 |
| Parameter: Sum_Capacity      | ParaVar Sum_Capacity                 | 硬盘总容量需求参数                              |
| Parameter: Sum_Memory        | ParaVar Sum_Memory                   | CPU总内存需求参数                             |
| Part: sd1, sd2, sd3          | @PartAnno(fatherCode = "drive", ...) | 固态硬盘实例                                 |
| Part: md1, md2, md3          | @PartAnno(fatherCode = "drive", ...) | 机械硬盘实例                                 |
| Part: cpu1, cpu2, cpu3, cpu4 | @PartAnno(fatherCode = "cpu", ...)   | CPU实例                                  |
| ConfigurationSolution        | inferRecommendModule()               | 配置求解入口                                 |
| ConfiguredPart               | ModuleInst 输出                        | 包含 Q(quantity), H(hidden), S(selected) |


### 4.4 需要保持的边界

1. **Module 不应兼任产品主数据仓库**。应由编译或适配层从已发布 ProductClass 业务模型生成 Module。ProductClass 自带 version 字段，不要再加 ProductClassVersion。
2. **现有 Part.price 只是单值**，不足以承载币种、区域、渠道、阶梯和有效期定价。业务模型应引用独立定价域。
3. **Spec 和 Parameter 的区别要保持**：
  - SpecDefinition 既可定义在 ProductClass 上也可定义在 PartClass 上，ProductClass 和 Part 都有自己的 SpecValue，描述产品或部件固有属性
  - Parameter 定义在 ProductClass 或 PartClass 上，对应的 Part 无 Parameter 值，描述用户可变的配置需求
4. **ProductInstance 可编译成裁剪后的 Module**，也可使用基础 Module 加候选集过滤输入。ProductInstance 自带 version，不要再加 ProductInstanceVersion。
5. **模型升级需要快照机制**。历史报价和 BOM 必须能够复现，不能因为模型变更导致历史配置无法验证。

## 八、附录

### 8.1 术语表


| 术语              | 全称    | 说明                                                                 |
| --------------- | ----- | ------------------------------------------------------------------ |
| SpecDefinition  | 规格定义  | 产品的物理特性或性能指标定义，Part 有对应 SpecValue                                  |
| SpecValue       | 规格值   | Part 的具体规格属性值                                                      |
| Parameter       | 参数    | 可由用户输入/修改的配置需求定义，Part 无对应 Parameter 值                              |
| ProductClass    | 产品类   | 产品族或平台的可复用骨架，承载平台化和标准化                                             |
| PartClass       | 部件分类  | 可配置子模块的分类边界，如 CPU、硬盘                                               |
| Part            | 部件    | PartClass 的具体实例，如 cpu1、sd1                                         |
| ProductInstance | 产品实例  | 确定销售边界的可售产品，对标电商 SPU                                               |
| offersPart 边    | 部件裁剪边 | ProductInstance 到 Part 的关系边，携带 enabled/default/minQty/maxQty/fixed |
| Configuration   | 配置方案  | 一次客户配置方案                                                           |
| ConfiguredPart  | 已选部件  | 配置方案中被选中的部件及其数量                                                    |
| ConfiguredValue | 已选参数值 | 配置阶段用户输入的参数值                                                       |


### 8.2 规格 vs 参数速查


| 问题                             | 答案                                          |
| ------------------------------ | ------------------------------------------- |
| 服务器外形（2U/4U）是规格还是参数？           | 产品类规格，因为外形是 ProductClass SERVER_X86 固有的物理属性 |
| 硬盘容量是规格还是参数？                   | 部件规格，因为容量是 Part sd1 固有的（3TB）                |
| 客户需要"至少 5TB 容量"是什么？            | 参数，因为这是用户可配置的输入需求                           |
| CPU 核心数是规格还是参数？                | 部件规格，因为核心数是 CPU 固有的（2/4/8/18）               |
| 客户要求"4 核 CPU 总内存 >= 512GB"是什么？ | 参数，因为这是用户可配置的筛选条件                           |
| Parameter 有 SpecValue 吗？       | 没有，Parameter 值在 Configuration 中由用户输入        |
| SpecValue 只挂在 Part 上吗？         | 不，ProductClass 也可以挂自己的 SpecValue（产品层规格）     |


### 8.3 数据流向总结

```
产品数据架构师
     ↓
创建 ProductClass（自帶 version） + PartClass → 定义 SpecDefinition → 定义 Parameter
     ↓
录入 Part + SpecValue → 录入 ProductClass 自身的 SpecValue → 发布 ProductClass = SERVER_X86
     ↓
产品数据工程师
     ↓
创建 ProductInstance (S1110@1.0.0 / S22@1.0.0，ProductInstance 自帶 version)
     ↓
通过 offersPart 边裁剪部件候选集 → 发布产品实例
     ↓
销售/客户
     ↓
选择 ProductInstance → 输入 Parameter 值 → 配置引擎求解
     ↓
输出 ConfiguredPart + BOM/报价/交付规格
```
